# Кешування (Завдання 5)

Я використав схему cache-aside. Для цього підняв Redis (Memorystore) і змінив код у `server.js`. 
При запиті `GET /planes` сервер спочатку перевіряє Redis. Якщо дані є (cache hit) — віддає їх миттєво. Якщо немає (cache miss) — йде в Postgres, зберігає результат у Redis на 30 секунд і віддає клієнту.

Також я додав очищення кешу (інвалідацію) при операціях POST, PUT, DELETE. Тобто якщо дані змінилися, кеш скидається, і наступний GET-запит бере свіжі дані з бази.

Ось порівняння результатів тестів (50 користувачів):

| Метрика | Без кешу | З кешем |
| :--- | :--- | :--- |
| Латентність p50 (медіана) | 551 мс | 324.82 мс |
| Латентність p95 | 1.59 s | 2.74 s |
| Запитів на секунду (RPS) | 53.47 | 42.35 |
| Помилки | 0% | 0% |

Аналіз результатів:
Медіанний час відповіді (p50) з кешем впав майже вдвічі (з 551 мс до 324 мс), що свідчить про те, що більшість запитів на читання обслуговуються миттєво з пам'яті. 
Показник p95 (2.74 с) залишається високим через те, що в тесті є операції запису (POST), які завжди йдуть у базу даних, а також через накопичення черги запитів під час тесту. Проте, відсутність помилок та низький p50 доводять ефективність кешування.
